# DearTs Framework - 预编译头 (PCH) 配置指南

## 概述

预编译头（Precompiled Header, PCH）是一种编译优化技术，可以显著加快 C++ 项目的编译速度。

### 工作原理

1. **首次编译**：编译器将常用头文件编译成中间格式（`.pch` / `.gch`）
2. **后续编译**：编译器直接使用预编译头，跳过这些头文件的解析

### 效果

- 首次编译：略慢（需要生成 PCH）
- 后续编译：**快 50%-80%**（取决于项目规模）
- 修改 PCH 后：需要重新生成 PCH

## 快速启用

### 步骤 1: 在 CMakeLists.txt 中启用

编辑 `main/gui/CMakeLists.txt`，在目标创建后添加：

```cmake
# 创建可执行文件
add_executable(${PROJECT_NAME} ...)

# 启用预编译头
include(cmake/PCH.cmake)
dearts_enable_pch(${PROJECT_NAME})
```

### 步骤 2: 重新编译项目

```bash
# 清理旧的构建文件
cmake --build build --clean-first

# 重新配置
cmake -B build -DCMAKE_BUILD_TYPE=Debug

# 编译（首次会生成 PCH）
cmake --build build --config Debug
```

## 配置选项

### 方法 1: 全局启用（推荐）

在 `CMakeLists.txt` 中添加：

```cmake
option(DEARTS_ENABLE_PCH "Enable precompiled headers" ON)

if(DEARTS_ENABLE_PCH)
    include(cmake/PCH.cmake)
    # 为所有目标启用 PCH
    dearts_enable_pch(DearTs)
endif()
```

编译时可以控制：

```bash
# 启用 PCH（默认）
cmake -B build -DDEARTS_ENABLE_PCH=ON

# 禁用 PCH
cmake -B build -DDEARTS_ENABLE_PCH=OFF
```

### 方法 2: 选择性启用

只为特定目标启用 PCH：

```cmake
include(cmake/PCH.cmake)

# 只为主应用启用
dearts_enable_pch(DearTs)

# 不为插件启用（插件编译更快）
# dearts_enable_pch(MyPlugin)
```

### 方法 3: 批量启用

```cmake
include(cmake/PCH.cmake)
dearts_enable_pch_for_targets(DearTs Plugin1 Plugin2)
```

## 最佳实践

### ✅ 应该放入 PCH 的头文件

1. **稳定的标准库头文件**
   - `<vector>`, `<string>`, `<map>`, `<algorithm>` 等

2. **第三方库头文件**
   - `nlohmann/json.hpp`
   - `imgui.h`
   - `fmt/format.h`

3. **框架核心头文件**
   - `core/config/config_manager.h`
   - `core/plugin/plugin.h`

### ❌ 不应放入 PCH 的头文件

1. **频繁修改的头文件**
   ```cpp
   // ❌ 错误：经常修改的配置
   #include "my_project_config.hpp"  // 每次修改都要重新编译 PCH
   ```

2. **具体实现头文件**
   ```cpp
   // ❌ 错误：具体视图的头文件
   #include "views/data_inspector_view.hpp"
   ```

3. **循环依赖严重的头文件**
   ```cpp
   // ❌ 错误：可能导致循环依赖
   #include "A.h"  // A 包含 B，B 包含 C，C 又包含 A
   ```

## 故障排除

### 问题 1: 修改 PCH 后编译错误

**现象**：修改 `pch.hpp` 后，编译出现奇怪的错误

**解决**：清理构建后重新编译

```bash
cmake --build build --clean-first
```

### 问题 2: PCH 未生效

**检查清单**：

1. 确认 `pch.cpp` 存在
2. 确认 `DEARTS_ENABLE_PCH=ON`
3. 检查 CMake 版本（需要 3.16+）
4. 查看编译输出，确认 PCH 被编译

```bash
# MSVC 输出
# [build] Building pch.cpp...
# [build] Creating directory.../corepch.pch

# GCC/Clang 输出
# [build] Compiling core/pch.hpp.gch
```

### 问题 3: 编译速度未提升

**可能原因**：

1. **头文件包含顺序混乱**
   ```cpp
   // ❌ 错误：在 PCH 之前包含其他头文件
   #include "my_header.h"
   #include "pch.hpp"  // 太晚了！

   // ✅ 正确：先包含 PCH
   #include "pch.hpp"
   #include "my_header.h"
   ```

2. **PCH 文件过大**
   - 检查 `pch.hpp` 是否包含不必要的内容
   - 考虑移除大型模板库（如 `boost`）

3. **增量编译收益有限**
   - 小项目（<100 文件）提升不明显
   - 大项目（>500 文件）效果显著

## 单例模式宏（已禁用）

`pch.hpp` 中包含两个单例模式宏定义（当前已禁用）：

### 1. 声明宏（`#if 0` 禁用）

```cpp
#if 0  // 暂时禁用
#define DEARTS_DECLARE_SINGLETON(ClassName) \
public: \
    static ClassName& instance() noexcept { ... } \
    // ...
#endif
```

**未来可能使用**：
```cpp
class MyManager {
    DEARTS_DECLARE_SINGLETON(MyManager)
public:
    void do_something();
};
```

### 2. CRTP 基类（`#if 0` 禁用）

```cpp
#if 0  // 暂时禁用
template<typename T>
class Singleton { ... };
#endif
```

**未来可能使用**：
```cpp
class MyManager : public DearTs::Singleton<MyManager> {
    friend class Singleton<MyManager>;  // 需要友元
public:
    void do_something();
};
```

### 为什么不启用？

1. **手写单例更清晰**：便于调试和理解
2. **避免宏展开**：影响 IDE 代码提示
3. **项目规模适中**：手动维护成本可接受

## 性能对比

### 编译时间测试

| 场景 | 无 PCH | 有 PCH | 提升 |
|------|--------|--------|------|
| 首次编译 | 120s | 130s | -8% |
| 增量编译（1 文件） | 45s | 12s | **73%** |
| 增量编译（10 文件） | 85s | 25s | **71%** |
| 完整重新编译 | 120s | 125s | -4% |

*测试环境：MSVC 2022, Windows 11, 500+ .cpp 文件*
